# 控制組抓到的判準失效：八層，而後四層不是控制組抓的

**日期**：2026-08-09
**來源事件**：ytlite 下載功能修復 + 資料損失事故（BRNS br=download-invisible）
**性質**：驗證方法論。**不是 ytlite 的缺陷**，故不進 `issues/`。

## 觀察

在同一個工作包內，三個**互相獨立**的判準各自失效，形狀完全相同——
「缺席態」與「成功態」共用同一個輸出：

| 層 | 判準 | 失效形狀 |
|---|---|---|
| 第一層　被測物 | `triggerFileDownload` 的 iframe fallback | 「不知道有沒有落地」與「成功」共用 `return true` |
| 第二層　handler 的 harness | `setTimeout` stub 從不呼叫 callback | 「跑 1 個」與「跑 10 個全通過」共用 `rc=0` |
| 第三層　dispatcher 的掃描器 | `grep -F` 吃 regex 轉義字串 `'?\.'` | 「語法不存在」與「pattern 打不中」共用 `0 命中` |

## 第四層：判準對「自己」沒有判別力（種類不同，不是第四次）

當天稍晚又出現一個，我起初把它歸成「同一形狀的第四個實例」——**那個分類是錯的，
handler 指出它屬於另一層**：

| | 判準沒有判別力的對象 |
|---|---|
| 第一～三層 | **被測物** |
| 第四層 | **判準自己** |

具體事實：dispatcher 的 mutation harness 用 regex 剝掉 arrow function body 的右括號
來合成 mutant，剝錯了，`eval` 丟語法錯 —— 而那個 harness 把它**報成「突變沒有被殺」**。

```
壞掉的 mutant    -> 沒有觀察到差異 -> 報「存活」
真正存活的 mutant -> 沒有觀察到差異 -> 報「存活」
```

「我打歪了」與「我打中了但它不痛」共用同一個輸出。而這發生在**專門用來抓這個形狀的
那個工具**身上。

**推論（本文件最重要的一句）：這個形狀沒有自然終點。** 每加一層判準，那一層自己就
成為新的候選失效點，**且它的失效方式與它要抓的東西同形**。所以「mutant 必須先斷言
可編譯」不是一條額外的小心，它是遞迴的下一層基底。

**唯一能收斂的做法是選一個在構造上無法靜默的形式**：

```
字串手術合成 mutant  -> 可以剝錯 -> 靜默降級成假陰性        ✗
函式合成 (j) => orig(j) || 新條件  -> 要嘛可編譯要嘛當場 throw  ✓
```

其他做法只是把遞迴推遲一層。

### 同族但更淺的一格：斷言「有沒有變」≠ 斷言「變得夠不夠」

handler 自己的 M3 突變用 `assert_replaced` 守住「完全沒替換就 `SystemExit`」，
但它攔不到「替換了、可是不夠徹底」（只換掉 `MEDIA_EXTS` 元組的前綴，`.webm` 還留著）。

```
可機械斷言   有沒有變        布林、便宜、已被守住
無法機械斷言 變得夠不夠      只能看實際輸出數字（回 1 筆 ≠ 回 0 筆）
```

這兩件事長期被當成同一個檢查，而它們不是。

## 第五層：每一格判準都是對的，聯集卻不含正確性條件

當天最後一輪，交付物帶著**六處使用者可見的錯字**（`似服器`，應為 `伺服器`）通過了
handler 全部六組驗證。

關鍵在於：**沒有任何一組壞掉**。每一組都誠實地量了它宣稱要量的東西。

| 驗證組 | 它量的東西 |
|---|---|
| V1 呼叫點 | `fetch` 與 `purge` 參數 |
| V2 位置 | `fetch` 落在哪個 span 內 |
| V3 filter | `status` 字串 |
| V4 渲染 | `purgeJobFile` / `隱藏` / `刪除檔案` 有沒有出現 |
| V5 iOS12 | 禁忌語法 |
| V6 語法 | 可不可編譯 |

V4 最接近而恰好錯過：它斷言 `'刪除檔案' in actions` —— 而 `刪除檔案` 是**對的**，
錯的是它旁邊那三個字。

```
第一～三層  判準對被測物沒有判別力     -> 可局部修（讓這層有判別力）
第四層      判準對自己沒有判別力       -> 可局部修（META 斷言 real != mutant）
第五層      判準集合的聯集 ∩ 正確性條件 = ∅   -> 加層無法收斂
```

**為什麼加層無法收斂**：再加一個「V7 錯字檢查」不會解決問題，只會再開一個
不重疊的維度。前四層的解法是「讓這層有判別力」；第五層必須**換一個與交付物同源的基準**。

### 能收斂的做法：用交付物自己已有的正確樣本當基準

`伺服器` 就在同一個檔案上下四百行內出現兩次。所以判準是：

> 新增使用者可見字串時，**逐詞**檢查該詞在同檔是否已有先例。

它與「V7 錯字檢查」的根本差別：後者需要一個**外部**正確性來源（字典），
前者的基準**就在被驗物裡面** —— 所以它不開新維度。

**但它必須帶上第二半**（handler 的縮窄，是必要的不是補充）：

```
有先例 -> 必須逐字相同（可機械化）
無先例 -> 這個判準對它「零覆蓋」，必須明說，不得默認通過
```

第二半不寫，這條規則自己就變成第五層的同一個病：**判準的沉默被讀成「通過」**。
本例中 `伺服器` 有先例所以抓得到；同輪新增的 `隱藏` / `刪除檔案` 沒有先例，
它們未被此判準覆蓋 —— 這句話必須出現在報告裡。

### 第五層有一個前四層沒有的性質：它無法被自己發現

前四層都能靠 META 斷言在同一支 harness 內抓到。第五層的每一格都會通報 PASS，
**而且那些 PASS 全部為真**。

它只能由**讀交付物的人**抓到。本例是 dispatcher 讀 diff 時抓到的，不是任何腳本。

## 第六層（同日稍晚，由使用者抓到）：判準的定義域不含「這個題目是否存在」

三件修復全部驗證通過、全部 live 之後，使用者實測回報：

> 「我看到檔案出現在我的本地資料夾了。所以我猜這個界面它判斷我已經下載好了，
> 才會瞬間清除而不通知。既然這樣，這個功能沒有再處理的必要了。」

**他是對的，而這推翻了整個工作包的前提。** 他原本報的症狀（一秒跳完成並清掉、
沒機會按下載）不是缺陷 —— 那是 `autoSaveJob` 在 `downloadDirHandle` 已授權下
拿到 `'confirmed'`（真的驗到本機副本落地）後 `purge=true` 的**正常成功路徑**。

三件修復沒有一件在治他報的症狀。它們仍然必要（刪檔事故的結構條件是真的），
但**「使用者報的症狀」與「我們找到的缺陷」是兩個不同的東西，而它們一路被當成同一個**。

```
第五層  判準的聯集不含「字對不對」      -> 讀交付物的人能抓到
第六層  判準的定義域不含「題目是否存在」 -> 只有實際使用的人能抓到
```

所有驗證問的都是「這個改動有沒有做到它宣稱的事」。**沒有一格在問
「使用者報的那件事是不是缺陷」** —— 那不在任何判準的定義域裡。

推論：第五層告訴我們「連讀交付物的人都需要」；第六層告訴我們
**連讀交付物都不夠，要讀使用者的實際使用**。這不是可以靠更嚴格的驗證補上的位置。

## 第七層（2026-08-09 稍晚，mp3-metadata 工作包）：判準在回答一個它沒被問到的問題

前六層講的是判準的**輸出端**。這一層在**輸入端**，而它有兩個對稱的實例，同一天各出現一次。

**實例 A — 輸入被清空，判準誠實回報成功。**

```
docker exec ytlite  python3 - <<'PY'   → 無輸出  rc=0     ← 程式從未執行
docker exec -i ...  同一份 heredoc     → MARKER   rc=0     ← 這才是執行了
```

沒帶 `-i` 時 stdin 未附加，`python3 -` 讀到 EOF 就跑了零行程式，然後正常 exit 0。
**「程式沒跑」與「跑完沒結果」共用同一個輸出，而且是最令人安心的那個（成功 + 空）。**

那一格資訊系統當下有沒有？——**有一半，而那一半正是問題所在**：`docker exec` 知道自己沒附加
stdin（是它自己決定的），`python3` 知道自己從 stdin 讀到 0 bytes。兩邊都知道，
**但沒有任何一邊認為「收到空程式」值得說一句話** —— 對 `python3 -` 而言空輸入是合法輸入。
這是 POSIX 語義不是可修標的，故不進 `issues/`。同族：`bun test <不存在的路徑>`。

**實例 B — 輸入被弄壞，判準誠實回報「殺死」。**

mutation 那一刀，把 `'key': 'FFmpegMetadata'` 替換成另一個不相容的 key：

```
CUT1   ok=False  files=[]  pics=-1    → tags 不見了 → killed=True   ← 假的
CUT1'  ok=True   files=['…mp3']  title=None  pics=1 → killed=True   ← 真的
       （改成移除整個 dict）
```

CUT1 的 tags 不見，**是因為根本沒有檔案，不是因為 tag 沒寫**。一個把被測物整個弄壞的 mutant，
與一個精準命中的 mutant，共用同一個 `killed` 輸出。

**這比「壞掉的 mutant 冒充存活」更難發現**（第四層那一格），因為 `killed` 是我們**想要**的結果——
沒有人會去質疑一個符合預期的綠燈。抓到它的是順手加的 scoped 斷言：
`CUT1 SCOPED (cover survives) = False` —— 這一刀影響了它**不該**影響的東西。

**兩個實例的共同結構**：都不是判準說謊，是**判準在回答一個它沒被問到的問題**。
A 問的是「這段程式的輸出是什麼」，實際回答的是「空程式的輸出是什麼」；
B 問的是「拿掉寫 tag 這一步會怎樣」，實際回答的是「把整條 postprocessor 鏈弄壞會怎樣」。

**處方（與前六層不同，這一層可以機械化）**：每一刀 mutation 都要有 **scoped 斷言**——
明確寫出它**不該**影響的東西，並斷言那些東西存活。`killed=True` 單獨不是證據，
`killed=True AND scoped=True` 才是。同理，任何「執行一段程式並讀它的輸出」的判準，
先讓那段程式印一個 marker，證明它真的跑了。

## 第八層（同包，我自己踩的）：知識在場但沒有在決策點被套用

驗證音樂影片分支時，我挑了 Lady Gaga 官方頻道的影片當樣本，拿到 `artist=None`，
於是那一格證明不了它宣稱要證明的事。

**而 handler 的報告裡明明寫了**：「分岔點是頻道是不是 `- Topic`，不是內容是不是音樂」。
我讀了那句話，然後挑樣本時沒有套用它。

這不是前七層的任何一種——判準沒壞，控制組沒壞，輸入沒被清空。
**是正確的知識在 context 裡，卻沒有在需要它的那個決策點被取用。**

**這一層與第五、六層同樣沒有自動化的位置**，但原因不同：第五層缺的是一個外部讀者，
第八層缺的是「把剛讀到的判準，在下一個動作前實際套一次」。唯一的處方是把它變成**顯式的一步**——
挑樣本時先寫出「這個樣本滿足哪個判準」，而不是憑印象抓一個看起來像的。

## 為什麼三層獨立是關鍵

**三層都不是被自己的正向結果抓到的，全部是控制組抓的。**

- 若只發生在一層，可歸因於那一層的人不夠仔細。
- 發生在三層、由三個不同的人／層在不同時間各自寫壞、卻是同一個形狀 ⇒
  **這是判準這種東西的固有失效模式，不是任何人的疏忽。**

第三層特別值得記：它發生在**最外層的稽核者**身上——那個人當輪才剛把
「缺席態與失敗態不得共用同一個輸出」寫進派工單、並用它抓到前兩層。

## 處方

1. **任何「回空／exit 0 即通過」的判準，使用前先證明它在該失敗時真的會非空／非零。**
   控制組不是形式主義，它是唯一能抓到自己判準壞掉的手段。
2. **測「它跑了幾個」而不只測「跑的那些過了沒」**（覆蓋率斷言）。
   `for` 迴圈靜默早退時，`FAILURES=0` 是真的，只是它只跑了一個。
   ```
   if (tested !== KEYS.length) fail(`only ${tested}/${KEYS.length} cases ran`)
   ```
3. **突變要打在被測物上，不是打在輸入上。**
   刀要落在護欄真正所在的那一格：
   - 打「預設值」而不只打「呼叫端」——預設為破壞性時，十個呼叫點寫對也保護不了未來第 11 個。
   - 打「rescan 產生的值」而不是「測試手捏的輸入」——後者證明的是 filter 的定義（恆真）。
4. **控制組必須與被測判準是同一個問題。**
   量「jq 讀不讀得到檔」不能證明「分不分得出缺席與 null」。
   同一天的實例：filter 控制組只餵 `completed`，於是 `activeDl`（濾 `queued`/`downloading`）
   正當地回 0 而被報成 FAIL —— 探針與被測判準問的不是同一個問題。
5. **合成，不要做字串手術**（第四層的處方）。
   凡「產生一個變體再執行它」的動作，選一個**在構造上無法靜默失敗**的形式；
   若非得做文字替換，就把「替換成功」與「替換徹底」當成兩個獨立斷言。
6. **一層判準的正向結果不能證明那層判準本身可用。**
   第一～四層的失效，**沒有一次是被自己的正向結果抓到的，全部是控制組抓的**。
7. **新增使用者可見字串，逐詞比對同檔先例**（第五層的處方）。
   有先例 ⇒ 必須逐字相同；**無先例 ⇒ 明說零覆蓋，不得默認通過**。
   基準在被驗物自己裡面，所以它不像「加一層錯字檢查」那樣再開一個不重疊維度。
8. **第五、六、八層沒有自動化的位置，不要再加層。**
   第五層需要一個讀交付物的人；第六層需要使用者真的去用；
   第八層需要「把剛讀到的判準，在下一個動作前實際套一次」——那是一個習慣不是一個檢查。
   把這三格寫成「再嚴格一點就能抓到」是誤歸責，它會讓下一個人把預算花在不會收斂的方向。
9. **每一刀 mutation 都要有 scoped 斷言**（第七層的處方，**這一層可以機械化**）。
   明確寫出它**不該**影響的東西，並斷言那些東西存活。
   `killed=True` 單獨不是證據，`killed=True AND scoped=True` 才是——
   否則一個把被測物整個弄壞的 mutant 會冒充成一刀精準命中。
10. **任何「執行一段程式並讀它的輸出」的判準，先讓那段程式印一個 marker。**
    證明它真的跑了。空輸入是合法輸入，而合法輸入產生的是成功形狀的輸出。
